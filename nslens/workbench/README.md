# Optical engineering workbench

This is a small executable environment for a language model to choose optical tools and
surface freedoms. The corpus was generated by explicitly labeled numerical scripts.
A local Qwen3-8B baseline has now been evaluated, and a train-only LoRA experiment is
implemented. See the local Qwen section below for results and reproducible commands.

The first domain is one 2-D transmitting element with independent entrance- and exit-side
quadratic, cubic, and quartic freeform departures. It reuses the existing continuous-spline
tracer and energy/route verifier. It is not the previous four-global-coefficient regression
experiment, and it does not yet support folded-route discovery or 3-D optical design.

**Tools exposed to a model**

| Tool | Decision or observation | Cost |
|---|---|---|
| `inspect` | Current coefficients, enabled freedoms, field/pupil error, route support, energy | Cached measurement |
| `enable` | Choose entrance, exit, or both; select polynomial powers | No trace |
| `perturb` | Test and apply a bounded coefficient edit | One coarse trace |
| `optimize` | Spend a declared allowance optimizing only enabled terms | Every internal probe is charged |
| `restore_best` | Return to the best previously measured coarse design | No trace |
| `verify` | Check the submitted geometry on a denser field/pupil grid | One dense trace; at most two |
| `finish` | Submit the current design | Ends interaction |

Each episode allows 24 candidate evaluations, one initial measurement, two optional dense
checks, and 16 tool actions. The final hidden 279-ray audit is outside the interactive
budget and is charged separately. A model's statement that it succeeded is never a label.

The fixed specification includes material, lens envelope, source fields, pupil, detector,
and acceptance thresholds. Unknown tool names, malformed arguments, disabled parameters,
and oversized optimization requests are rejected. Invalid requests consume an action slot.
No tool permits shell execution, arbitrary code, access to files, or reading a witness.

**Run the numerical corpus and audit**

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python \
  -m nslens.workbench.episodes \
  --out runs/optical_workbench_new --workers 10

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python \
  -m nslens.workbench.audit runs/optical_workbench_new --workers 10

.venv/bin/python -m unittest discover -s tests -p test_optical_workbench.py
```

Use a new output directory. `private_certification.json` contains solver witnesses and
certification evidence. It must never be supplied to a learner or model endpoint. Public
tasks contain only requirements and the starting prescription. Splits are assigned at
the complete family level before generating any sibling tasks or plan alternatives.

`train_episodes.jsonl`, `validation_episodes.jsonl`, and `test_episodes.jsonl` retain all
plans, tool observations, rejected internal edits, and final outcomes. The conversations
contain actual executed function calls and their measured outputs; no reasoning narrative
is manufactured. `train_sft.jsonl` contains only successful submitted training episodes.
`train_plan_preferences.json` ranks complete plans from identical starting states; these
are not mislabeled as isolated-action counterfactuals. Rank is verified success, physical
validity, then final RMS; the candidate allowance is identical but actual use can differ.

**Run a frozen language model**

Configure `OPENAI_API_KEY` and an explicit `OPTICS_MODEL` in the process environment.
For a compatible server, optionally set `OPTICS_BASE_URL`; the default is
`https://api.openai.com/v1`. No model name is chosen silently. The endpoint must support
the Responses API with function calling. A local endpoint that ignores authentication
can use its documented placeholder key. The runner never reads login tokens from other
applications or stores API credentials in artifacts.

```bash
.venv/bin/python -m nslens.workbench.model_baseline \
  runs/optical_workbench_pilot_20260910_v1 \
  --out runs/optical_workbench_frozen_baseline --limit 4
```

The initial four-task smoke run uses held-out test tasks. Model calls, reported token
usage, actual returned model metadata, tools, evaluations, protocol failures, and final
audits are recorded. Transport errors are failures, not substituted numerical-policy
results. Request count and per-response output are capped. The cumulative token guard
is checked between requests; a request's newly reported input usage can cross that guard.
Use a pinned model version when available. The model is not fine-tuned during this run.

The implementation follows the [official Responses function-calling protocol](https://developers.openai.com/api/docs/guides/function-calling):
execute returned `function_call` items and send matching `function_call_output` items
back to the model. Offline tests exercise this protocol with a test fixture; they are
not evidence of a successful live API run.

**What the first pilot establishes**

The first pilot generated 36 tasks from 12 certified families, with four scripted plans
per task: all terms, entrance-only, exit-only, and staged polynomial order. It produced
144 episodes, 54 successful training conversations, and 18 training plan preferences.
There are 35 failed episodes, retained with their full measurements. Held-out test data
contains 12 tasks from four families, with 48 plan runs.

Enabling every term already solves every pilot task. This is a useful executable baseline,
but it means binary success in this corpus is too easy to demonstrate sophisticated
engineering judgment. Final error and trace use distinguish plans; a stronger benchmark
should add physically justified surface-access, fabrication, or packaging constraints,
then re-certify solvability. Do not infer LLM competence, training benefit, or an AZR
curriculum advantage from these scripted results.

**Local Qwen baseline and LoRA experiment**

The local runner uses Qwen3-8B directly through Transformers; it needs no API key.
See [measured Qwen results](../../agent_context/ns_systems/qwen_optical_workbench_results.md).
The baseline completes 12/12 test tasks at a 64k cumulative token ceiling. The original
24k setting cannot accommodate any full teacher conversation in the native Qwen format.
The local transport now reserves input tokens before generation, enforcing a hard cap.

Evaluate the adapter using the first command plus `--adapter runs/qwen_lora_new/adapter`
and another new output directory. Keep the task list, sampling seed, language-token
ceiling, and physical budgets identical. `compare_qwen` checks these configurations
(except explicitly varied token ceilings), counts non-submissions as failures, and reports
optical quality separately from submission success. A reduction in training loss alone
is not an engineering improvement.

**Folded freeform scope (current priority)**

The folded domain now uses a closed freeform prism and actual TIR paths. Frozen
Qwen completes two audited repairs at a 128k cumulative language ceiling; both
share one ancestor, and a fixed numerical control also succeeds. This establishes
a folded tool environment, not a learning advantage or architecture discovery.
See [folded results, PNGs, limitations, and commands](../../agent_context/ns_systems/folded_qwen_workbench.md).
Further unfolded adapter evaluations are parked.

The [constrained decision pilot](../../agent_context/ns_systems/folded_decision_benchmark.md)
now screens archive candidates and enforces per-task surface access, change bounds,
and trace budgets. Frozen Qwen solves 3/4 development tasks; a post-hoc fixed numerical
plan solves 4/4. This set is not ready to support a learning claim.

**Executed pencil-beam learning loop**

See [the two-round Qwen curriculum experiment](../../agent_context/ns_systems/pencil_qwen_learning_results.md).
It uses 1 mm fields, verified folded repairs, and eight bounded numerical plans.
Actual LoRA updates improve primary test success from 0/4 to 3/4 for adaptive and
fixed curricula; uniform training does not improve. This is a small finite-pool
planner experiment, not learned task synthesis or a proven adaptive-over-fixed advantage.

**Wider-angle refinement of interrupted discovery results**

The September 12 development run is in
`runs/angular_qwen_20260912_v1/`. Its `REPORT.md`, `dense_verification.json`, and
`designs/manifest.json` describe the completed results when available. The six tasks
preserve beam width, receiver, material, codec bounds and initial body dimensions.
Targets are the next failed sampled wider range, capped at 12° full input width;
one start already passed 12° and is explicitly a preservation case.

`stock_probe` now accepts per-task `full_fov_deg`, `batch_limits`, and `instructions`.
Legacy defaults remain 1° repair/compaction, 2° field expansion, and two batches per
probe. The angular tasks declare only `field`, with six 40-proposal batches and their
actual target width. A fixed numerical control uses the same candidate allowance.
Post-search checks add angular samples and compare 200k/400k branch capacities.
These are 2D routing checks; imaging quality is not measured.

To resume existing unfinished Qwen tasks with their saved state:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .venv/bin/python \
  -m nslens.workbench.stock_probe run runs/angular_qwen_20260912_v1/qwen \
  --endpoint http://127.0.0.1:8080/v1 --model qwen3.8-27b --workers 2
```

The local model server must use the recorded inference settings. Completed tasks
return their saved outcomes; candidate batches and model responses are retained.
