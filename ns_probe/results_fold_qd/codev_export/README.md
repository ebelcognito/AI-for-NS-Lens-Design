# Fold designs → CODE V export

Generated by [`ns_probe/export_fold_for_codev.py`](../../export_fold_for_codev.py).

## What you get, per design
- `<id>.spec.txt` / `.spec.json` — the **exact, unambiguous geometry**: object/field,
  aperture stop, and one row per sequential surface (global vertex `YDE/ZDE`, tilt
  `ADE`, cylinder radius `RDY`, reflective?, medium after). This is the source of truth.
- `<id>.seq` — a **best-effort CODE V command-language macro** built from that spec.

## Coordinate mapping (2-D meridional → CODE V)
```
CODE V  Z = engine x   (optical axis / propagation)
CODE V  Y = engine y   (meridional transverse)
CODE V  X = out of plane   → curved faces are CYLINDERS along X (not spheres!)
```
The design was optimised purely in the meridional plane, so each curved face is a
**cylinder** (`RDY` finite, `RDX` = flat). A sphere would change the physics.

## How the fold is modelled
- The non-sequential TIR path (`dom_signature`, e.g. `T@A → TIR@D → TIR@B → TIR@B → T@B`)
  is unrolled into a **sequential** surface list.
- Every surface sits in **one global frame**: absolute `YDE/ZDE` vertex + `ADE` tilt,
  `THI = 0`, **decenter-and-return (DAR)**. The same physical face reused N times is
  emitted N times with identical numbers.
- **TIR hits → `TIRO` surfaces** (TIR-only, uncoated) that reflect and keep the ray inside
  glass `n` — matching the engine's lossless-TIR physics.
- Curved faces are emitted as **spheres** (`RDY` only). In the meridional plane a sphere and
  a same-radius cylinder trace identically, so this reproduces the 2-D design exactly.
  Convert them to Y-cylinders/toroids in the lens editor if you want the (unconstrained)
  sagittal to stay flat.
- Glass = a **constant-index model glass** `FOLDN` via the private catalog (monochromatic;
  the search used a fixed index, no dispersion).
- Object = infinity (`SO 0 1e18`); single field `YAN = ang`; beam diameter via `EPD`. The
  input beam's offset is reproduced by a **decentred aperture stop** (S1) at engine x = 0.

## Before you trust the trace (do this in CODE V)
The syntax was corrected against a live CODE V trace (`S` takes no index; `SO 0 1e18`;
`TIRO` for TIR; private-catalog glass confirmed working). After the trace, physics checks:
1. **Radius sign** — flip an `RDY` sign if a curved face bends the wrong way.
2. **`ADE` / `YAN` handedness** — negate if the beam folds the wrong direction.
3. **Ray actually TIRs** — `TIRO` errors if a surface's incidence is below the critical
   angle; if so the fold geometry/sign needs a look (or swap `TIRO`→`REFL` to force it).

The `.spec.txt` numbers are exact, so any of these is a one-line fix. Once it traces,
`VAR` the radii / tilts / image distance and optimise normally.

